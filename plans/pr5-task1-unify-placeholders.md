# ПР-5. Задача 1. План унификации плейсхолдеров и блоков конфиденциальности

> Первая из трёх задач ПР-5 (источник расхода контекста — «чтение нескольких материалов»).
> Находки аудита зафиксированы в `materials/privacy-audit-findings.md` (коммит `d127de7`).
> Этот план — выполнение рекомендации из аудита отдельным коммитом.

---

## Контекст

Аудит (задача 2 ПР-5) нашёл 3 расхождения в 5 файлах материалов. Утечек реальных
персональных данных нет — расхождения только в оформлении:

1. **Маркер «вне git» у зарплатных плейсхолдеров.** Есть только в
   `key-employees-registry.md` (`[заполнить: конфиденциально, вне git]` ×12).
   В `key-employees-salary-monitoring.md` — `[заполнить]` без маркера,
   в `welcome-meeting-questions.md` — `[заполнить: сумма]` без маркера.
2. **Абзац о конфиденциальности.** Есть в `key-employees-registry.md` и
   `key-employees-salary-monitoring.md`. Отсутствует в `vacancy-review.md`,
   `new-employee-first-day.md`, `welcome-meeting-questions.md`.
3. **Формат плейсхолдера (правило 9 `CLAUDE.md`).** В
   `key-employees-salary-monitoring.md` — укороченные `[заполнить]` / `[определить]`
   без описания. Остальные файлы используют `[заполнить: …]`.

## Решения (согласованы с пользователем)

1. **Эталон зарплатного плейсхолдера** — `[заполнить: конфиденциально, вне git]`
   (как в `key-employees-registry.md`). Применить ко всем зарплатным плейсхолдерам.
2. **Абзац о конфиденциальности** — единый раздел «Важное о конфиденциальности»
   во всех трёх файлах, где его нет. Текст одинаковый, по образцу из
   `key-employees-salary-monitoring.md`, адаптированный по сути.
3. **Унификация — только зарплатные плейсхолдеры.** Не-зарплатные (столбец
   «Статус» = `[определить]` и т. п.) НЕ трогать. Чистка лишних «вне git» у
   не-зарплатных полей — отдельная отложенная задача
   (см. память `salary-marker-outside-git-cleanup`).

## Этап 1. `key-employees-salary-monitoring.md` — зарплатные плейсхолдеры

В сводной таблице (строки 32–43) столбец «Ваша ЗП (заполняете сами)» содержит
`[заполнить]` ×12. Заменить ВСЕ 12 вхождений на `[заполнить: конфиденциально, вне git]`.

- Столбец «Статус (определяете сами)» = `[определить]` — НЕ трогать (не-зарплатное).
- Раздел «Важное о конфиденциальности» уже есть — НЕ добавлять.

## Этап 2. `welcome-meeting-questions.md` — зарплатный плейсхолдер + раздел

- Блок 2, пункт 4 (строка 34): `[заполнить: сумма]` → `[заполнить: конфиденциально, вне git]`.
- Добавить раздел «Важное о конфиденциальности» после блока «Вступление» (перед
  «Блок 1»). Существующая фраза про плейсхолдеры (строка 14) остаётся — она про
  механику заполнения, не про конфиденциальность как таковую.

## Этап 3. `vacancy-review.md` — раздел о конфиденциальности

- Зарплатных плейсхолдеров нет (это чек-лист) — менять нечего.
- Добавить раздел «Важное о конфиденциальности» после блока «Вступление»
  (перед «Чек-лист проверки»). Текст адаптировать под суть файла: чек-лист не
  хранит данные, а проверяет их отсутствие в тексте вакансии.

## Этап 4. `new-employee-first-day.md` — раздел о конфиденциальности

- Зарплатных плейсхолдеров нет (суммы не пишутся, только упоминается «до вычета
  НДФЛ» как формат). Менять нечего.
- Добавить раздел «Важное о конфиденциальности» после блока «Вступление»
  (перед «До начала рабочего дня»). Текст адаптировать: шаблон инструкции, реальные
  данные заполняются только в рабочем экземпляре.

## Этап 5. `key-employees-registry.md` — без изменений

- Зарплатные плейсхолдеры уже в эталонном формате — не трогать.
- Раздел о конфиденциальности уже есть (пункты 1–2) — не трогать.

## Текст раздела «Важное о конфиденциальности»

Единый каркас (суть одна, вводная фраза адаптируется под файл):

> ## Важное о конфиденциальности
>
> Этот файл — шаблон/отчёт, который сам по себе **не хранит** реальные персональные
> данные сотрудников (ФИО, телефоны, адреса, паспортные данные, ИНН, СНИЛС,
> зарплаты). Все конкретные значения помечены плейсхолдером `[заполнить: …]`.
> Реальные данные вписываются только в отдельном (локальном, не коммитимом)
> экземпляре файла и не попадают в git.

## Этап 6. Проверка

- `grep -rn "\[заполнить\]"` без описания — убедиться, что в
  `key-employees-salary-monitoring.md` зарплатные поля теперь с маркером.
- `grep -rn "вне git"` — убедиться, что маркер стоит только у зарплатных
  плейсхолдеров, не-зарплатные не задеты.
- `grep -rn "Важное о конфиденциальности"` — убедиться, что раздел есть во всех
  5 файлах.
- Проверить, что не-зарплатные плейсхолдеры (`[определить]`, `[заполнить: ФИО …]`
  и т. д.) остались без изменений.

## Ограничения

1. Менять **только** 4 файла: `key-employees-salary-monitoring.md`,
   `welcome-meeting-questions.md`, `vacancy-review.md`, `new-employee-first-day.md`.
   `key-employees-registry.md` не трогать (там уже эталон).
2. Не трогать не-зарплатные плейсхолдеры — никаких «вне git» у полей «Статус»,
   «ФИО», «контакт» и т. п.
3. Не вписывать и не вытаскивать реальные данные — только менять формат
   плейсхолдеров и добавлять текстовые разделы.
4. Не менять содержательные данные (рыночные суммы, примеры вакансий, пороги
   риска) — только оформление плейсхолдеров и блоки конфиденциальности.
5. Правки — отдельным коммитом, не смешивать с аудитом (аудит уже в `d127de7`).
