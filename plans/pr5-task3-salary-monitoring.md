## План реализации: сводный мониторинг по нескольким ключевым позициям

**Цель:** один файл, где по каждой ключевой позиции есть разбивка по площадкам и своя рекомендация, плюс общая картина в одной таблице.

### Что получится на выходе

Новый файл `materials/salary-monitoring-multi.md`. Структура:

1. **Заголовок и назначение** — мониторинг рыночного уровня ЗП по нескольким ключевым позициям (на конкурентные цели, не retention).
2. **Общие параметры** — площадки (HH, SuperJob, Rabota.ru, Zarplata.ru + справочно trudvsem.ru), регион по умолчанию (Чувашия), оговорка про формат НДФЛ.
3. **Сводная таблица** — по каждой позиции: мин / средняя / макс / число вакансий / краткая рекомендация. Даёт общую картину сразу.
4. **Блок по каждой позиции** (компактнее, чем в `salary-report.md`):
   - параметры (регион, формат, опыт);
   - разбивка по 4 площадкам + trudvsem (мин / средняя / макс / вакансий);
   - кратко про отсев линейных позиций;
   - мини-вывод и рекомендация по этой должности.
5. **Общий вывод** — состояние рынка по всем позициям, ограничения.
6. **Общие рекомендации** — что monitored дальше, где данных не хватает.

### Источник данных

Данные уже есть в существующих файлах — новый сбор не нужен:
- по 4 площадкам везде «Нет данных» (блокируют автосбор) — это установлено в `salary-report.md`, применю единообразно ко всем позициям;
- по trudvsem — рыночный коридор по 12 позициям есть в `key-employees-salary-monitoring.md`;
- параметры и обязанности — из `key-employees-registry.md`.

### Этапы

1. Зафиксировать список позиций (по умолчанию — 12 из реестра).
2. Свести данные по каждой позиции: параметры + коридор из registry/monitoring.
3. Оформить блок по каждой позиции: параметры → разбивка по площадкам → отсев → мини-вывод/рекомендация.
4. Собрать сводную таблицу.
5. Написать общий вывод и рекомендации.
6. Создать файл `salary-monitoring-multi.md`.
7. Коммит по конвенции: `docs(salary-monitoring): …`.

### Чем пожертвуем

- Глубиной по каждой позиции — блок компактнее отдельного отчёта, меньше места под детальный отсев.
- Файл длинный, читать целиком неудобно (но зато общая картина в одной таблице сверху).

### Правила и ограничения (по CLAUDE.md + прошлым договорённостям)

- Не придумывать данные — где их нет, писать «Нет данных».
- Суммы — до вычета НДФЛ; где источник (trudvsem) не уточняет формат — оговаривать отдельно, пересчёт не делать.
- В анализ брать только руководящие позиции; линейные отбрасывать с кратким пояснением.
- Реальные зарплаты действующих сотрудников не хранить — только плейсхолдеры; рыночные суммы можно.
- Обезличивание: «Сотрудник N» или название должности, без ФИО.
