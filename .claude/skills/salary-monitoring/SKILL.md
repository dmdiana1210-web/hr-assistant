# Мониторинг рыночных зарплат

## 1. Режим запуска

| Режим | Когда | Список должностей | Файл отчёта |
|---|---|---|---|
| `key` | ежемесячно, 7-го числа | `materials/key-employees-registry.md` | `materials/key-employees-salary-monitoring-ГГГГ-ММ.md` |
| `all` | апрель и октябрь, 7-го числа | `materials/all-employees-registry.md` | `materials/salary-monitoring-all-ГГГГ-ММ.md` |

- Если режим не указан — спросить у пользователя, какой режим нужен.
- В апреле и октябре режим `key` отдельно не запускается: ключевые
  сотрудники входят в отчёт `all`.
- Если файл со списком должностей не найден — остановиться и сообщить
  «Нет данных: не найден список должностей». Список не придумывать.

## 2. Предыдущий отчёт

- Найти последний отчёт этого же режима в `materials/`.
- Взять из него поисковые запросы — для сопоставимости повторять те же.
- Если предыдущего отчёта нет — в отчёте указать «Первый мониторинг,
  сравнения нет».

## 3. Сбор данных по площадкам

Каждую площадку собирать и показывать отдельно. Не сводить в одну цифру.

**HH (основная площадка):**
- api.hh.ru закрыт (ответ 403). Читать страницы поиска:
  `https://cheboksary.hh.ru/search/vacancy?text=<запрос>&area=<код>&only_with_salary=true&search_field=name&items_on_page=100`
  с браузерным User-Agent.
- Данные — в `<template id="HH-Lux-InitialState">` → `vacancySearchResult.vacancies`,
  поле `compensation` (`from`, `to`, `gross`).
- Если `totalResults` = 0 — HH подставляет «рекомендованные» вакансии,
  их отбросить.
- Коды регионов: Чувашия 1652, Татарстан 1624.

**SuperJob, Rabota.ru, Zarplata.ru:**
- Попробовать открыть страницу поиска по каждому запросу.
- Если страница не открылась или данных нет — записать «Нет данных» и
  причину (например, «ответ 404»).

**trudvsem.ru (справочно, не входит в список площадок):**
- Коды регионов: Чувашия 21, Татарстан 16.
- Показывать отдельным разделом. Не использовать для рекомендации —
  там в основном госсектор, цифры занижены.

Сырые данные и скрипты сохранять в `.cache/ГГГГ-ММ/` (не попадает в git).

## 4. Отбор вакансий

- Брать только вакансии с похожими обязанностями — сверять с обязанностями
  из списка должностей.
- Дубли одной вакансии считать один раз.
- **Режим `key`:** только руководящие позиции; линейные отбрасывать с
  кратким объяснением.
- **Режим `all`:** уровень вакансии должен совпадать с уровнем должности
  (руководитель — с руководителями, специалист — со специалистами).
- По каждой отброшенной группе вакансий — одна строка «почему не взята».

## 5. НДФЛ

- Все суммы — до вычета НДФЛ.
- Если у вакансии указано «на руки» — пересчитать в «до вычета» (÷ 0,87).
- Если формат не указан — не пересчитывать, пометить «формат не уточнён».

## 6. Расчёт

- «Средняя» — медиана по нижним и верхним границам вилок.
- Отдельно — «только коммерция» (без бюджетных, казённых, унитарных
  учреждений, министерств, администраций, МВД, УФСИН, компаний с
  госучастием).
- Изменение к предыдущему мониторингу — в процентах.

## 7. Шкала выводов (оба режима)

Отклонение = (внутренняя ЗП / рынок × 100) − 100.

| Отклонение | Вывод | Рекомендация |
|---|---|---|
| выше +15% | переплата | «Повышение не требуется» |
| от +10% до +15% | переплаты нет | «Корректировка не требуется» |
| от −7% до +10% | в рынке | «Корректировка не требуется» |
| ниже −7% | ниже рынка | развёрнутая рекомендация (см. раздел 9) |

## 8. Внутренняя ЗП

- Файл с зарплатами даёт пользователь (кладёт в «Загрузки» и просит
  посчитать). Запуск по расписанию ЗП не считает — только рынок.
- Режим `key` — средняя за 3 месяца, заканчивая позапрошлым месяцем
  относительно запуска (запуск 7 ноября → июль–сентябрь). Данные только
  за 1 месяц — ячейку не заполнять, сообщить пользователю.
- Режим `all` — средняя за последние 6 месяцев. Данные только за
  1–2 месяца — ячейку не заполнять, сообщить пользователю.
- Нулевые и пустые месяцы не считать.
- Смена фамилии — месяцы под старой и новой фамилией объединять.
  Однофамильцев с разным отчеством не склеивать.
- Премия руководителей — раз в полгода, от 50 000 до 100 000. Без точной
  суммы добавлять оценочно 12 500 в месяц (75 000 за полгода) и писать в
  выводе «премия учтена оценочно».
- Список получателей премии в навык не записывать — уточнять у
  пользователя перед каждым запуском.

## 9. Запись в Google-таблицы (режим `all`)

Таблицы искать по названию в Google Drive. ID таблиц в git не записывать.

**«Обновленный HR»:**
- Вкладка «ОБЩАЯ»: J — рыночный ориентир, K — дата мониторинга.
- Вкладки «Профили вакансий …»: после строки «Рекомендации:» вставить
  строку «Мониторинг от ДД.ММ.ГГГГ» — по каждой должности ориентир,
  площадка, регион, число вакансий, «предварительно» при < 10 вакансий.

**«Аналитика сотрудников ГК АвтоОка»** (вкладки по направлениям и
«Для Алексея и Руслана»):
- C — средняя ЗП без премии, F — рынок, H — «Месяц ГГГГ», I/J — вывод и
  рекомендация по шкале из раздела 7.
- На вкладках, где есть получатели премии (ПК АвтоОка, УЦ Энергия, Касма,
  Бухгалтерия, «Для Алексея и Руслана»): D — премия в месяц (оценочно,
  пусто у тех, кто её не получает), E — итого `=Cn+Dn`, G — формула
  `=(En/Fn*100)-100`.
- На остальных вкладках столбцов премии нет: C — ЗП, D — рынок,
  E — формула `=(Cn/Dn*100)-100`, F — «Месяц ГГГГ», G/H — вывод и
  рекомендация.
- Перед записью сверить заголовки вкладки — структура могла измениться.
- При недоплате больше 7% писать развёрнуто: что делает сотрудник, с
  какими вакансиями сравнивали, сколько их, надёжность цифры, шаги.

**Порядок:**
1. Сохранить старые значения в резервную копию (вне git).
2. Показать пользователю, что будет записано. Записывать только после «да».
3. Зарплаты из таблиц в git не переносить.

## 10. Отчёты руководителям в Битрикс24 (режим `all`)

**Данные.** Все ФИО и ЗП — только в `.cache/salary-reports/ГГГГ-ММ/data.json`
(вне git). Структура: `month`, `period`, `reports[]` — у каждого отчёта
`id`, `title`, `heading`, `kind` (`dept` — отдел, `directors` — Руслан/Алексей),
`greeting`, `region`, `recipient` (`name`, `bitrix_id`), `rows[]`
(`name` «Фамилия И. О.», `zp`, `market`, `note`, у `directors` ещё
`premium`, `comment`, `conclusion`). Новый месяц — копия прошлого
`data.json` с обновлёнными ЗП и рынком.

**Сборка и отправка** (Python с `matplotlib` и `openpyxl`):
- `scripts/build_reports.py <data.json> <папка>` — PNG и Excel на каждый отчёт.
- `scripts/send_report.py <data.json> <папка> <id> <ID Битрикс> ["заголовок"]` —
  вебхук из Связки ключей («HR Битрикс24»), вывод маскировать:
  `sed -E 's#https?://[^ ]*#[скрыто]#g'`.

**Формат сообщения:** вступление + картинка-таблица + Excel. После файлов
ничего не писать (без «итога», «что предлагаю», «давай обсудим»).
- Вступление: «Привет, {Имя}! Закончила полугодовой мониторинг зарплат,
  делюсь результатами по твоему отделу. / Коротко, как считала / Сравнила
  зарплаты сотрудников отдела с вакансиями конкурентов на HH ({регион}).
  Брала середину рынка, все суммы до НДФЛ. Наши цифры — средняя за {период}.»
- Таблица: №, Сотрудник, ЗП сотрудника, Рынок, Отклонение, Статус, Вывод;
  сортировка от большего отставания. «Кто не в рынке» — только внизу Excel.
- Вывод — только факты рынка, **без рекомендаций** (решения принимает
  руководитель): < −15% «Ниже рынка на N ₽. Есть вероятность, что
  сотрудник начнёт присматриваться к вакансиям»; −15…−7 «Ниже рынка на
  N ₽»; −7…+10 «В рынке»; +10…+15 «Немного выше рынка»; > +15 «Выше рынка».
- Руководителю — только его отдел, **без его собственной ЗП**.
- Пометки в выводе в скобках: неполный день, данные за 1–4 мес., другой
  регион рынка, ЗП уточняется.

**Отчёты для Руслана и Алексея** (`kind: directors`, вкладка «Для Алексея
и Руслана»):
- Руслан — руководители ПК АвтоОка, руководитель маркетинга и маркетолог
  ПК АвтоОка; Алексей — остальные руководители и прямое подчинение
  (без главбуха).
- Дополнительный столбец «Комментарий»: чем занимается, с чем сравнивали,
  сколько вакансий, надёжность, предложение. Тексты согласовывает
  пользователь (может прислать правленый Excel — брать изменения из него,
  но не откатывать более поздние решения).
- У получателей премии в выводе — «С премией ~12 500 ₽/мес (оценка)».

**Кто проверяет перед отправкой:**
- Отчёты отделов — сразу руководителю (по решению пользователя от 28.10.2026).
- Отчёты для Руслана и Алексея — **сначала пользователю на проверку**
  с заголовком «[НА ПРОВЕРКУ — …]», директорам — только после «да».
- После отправки — отметка во вкладке «Рассылка руководителям»
  (ID, «да, ДД.ММ.ГГГГ (картинка + Excel)»).

**Рынок для руководителей без прямых вакансий** — искать по обязанностям
в Чувашии (название + текст вакансии на HH). Если в Чувашии нет — соседние
регионы (Марий Эл, Татарстан, Ульяновская, Пензенская, Кировская обл.,
Ижевск) и пометить «нижняя граница», если сравнение с менеджерами.

## 10а. Автозапуск

| Когда (МСК) | Режим | Что делает | Куда |
|---|---|---|---|
| 7-го, 9:00, кроме апреля и октября | `key` | рынок по 12 ключевым | отчёт пользователю |
| 7 апреля и 7 октября, 9:00 | `all` | рынок по всем → отчёты | отделы — руководителям, Руслан/Алексей — пользователю |

- ЗП автозапуск не считает. Если файла с ЗП за нужный период нет
  (в «Загрузках» не обновлялся больше 30 дней) — **руководителям не
  отправлять**, только сообщить пользователю в Битрикс, что нужен файл.
- Запуск идёт на MacBook пользователя — ноутбук должен быть включён.

## 11. Конфиденциальность (проверить перед сохранением)

- [ ] В отчёте нет реальных зарплат сотрудников. На их месте —
      `[заполнить: конфиденциально, вне git]`.
- [ ] Сотрудники обозначены только как «Сотрудник N».
- [ ] ФИО индивидуальных предпринимателей из `company.name` заменены на
      «ИП (частный работодатель)» или «Бренд (ИП)».
- [ ] В отчёте нет телефонов, адресов и других персональных данных.

## 12. Структура отчёта

1. Назначение отчёта, дата сбора, предыдущий мониторинг
2. Важное о конфиденциальности
3. Шкала выводов (раздел 7)
4. Источники и статус каждой площадки
5. Формат сумм (НДФЛ)
6. Метод
7. Сводная таблица (графы «Ваша ЗП» и «Статус» — плейсхолдеры)
8. Детализация по каждой должности, разбивка по площадкам
9. Вывод: динамика, качество данных
10. Рекомендация по конкурентной зарплате — по порогам из
    `.claude/rules/salary-rules.md` (≥ 10 вакансий — надёжная,
    1–9 — предварительная, 0 — не формируется)

Рядом сохранить таблицу Excel с тем же именем (`.xlsx`).

## 13. Завершение

- Не сохранять в git автоматически. Показать пользователю краткую сводку:
  по скольким должностям есть данные, по каким площадкам «Нет данных»,
  где произошли резкие изменения (больше 20%).
- При запуске по расписанию — сохранить отчёт в отдельную ветку
  `docs/salary-monitoring-<режим>-ГГГГ-ММ` и не объединять с main.
